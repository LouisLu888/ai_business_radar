# 用来源真实性、任务恢复和手机闭环验收

本文件描述实现后的验证计划。当前没有应用代码，未执行单元、集成或端到端测试。

## 有风险的纯逻辑使用单元测试

- 日归档和日任务幂等：夏令时切换、UTC 跨日、漏触发后的补跑。
- URL 规范化、平台 ID 去重、同集多平台关联、错误合并撤销后收藏行为。
- 经营数字与币种/周期口径、缺正文时禁止生成正式摘要、引文与时间位置验证。
- JSON schema 失败、部分正文、同名嘉宾、仅被提及、推广内容的分类。
- 并发预算预留、调用失败后的结算、重复任务不二次扣款；固定本人来源优先、低置信候选日上限及恢复顺序。

## 本地集成验证数据库与任务边界

使用 Cloudflare 本地运行环境、测试 D1/R2 和虚构 RSS/字幕 fixture，真实正文不进公开仓库。覆盖 200/304/403/429/5xx、源站超时、feed 回溯、日期缺失和坏 XML。

完整度用例分别检查来源覆盖和处理覆盖：RSS 明示只有摘要、API 返回 200 但带有明确缺段标记、处理只读前 2,000 字符、部分分块失败。带这些可观察信号的材料均不得标为完整；重叠分块须按范围并集检查。没有来源范围依据但已处理全部取得文本时，显示范围未确认。

另设一个首尾正常、没有缺段信号但中间丢失的样本，由人工对照原作发现并验证降级和重处理；不要求代码从无信号中自动识别。白名单内容的标题没有 AI 或播放量低时，仍须取得正文再判定，或者明确留在待处理列表。

构造大量搜索候选与少量本人来源同时到达的场景，确认付费处理先服务本人来源、低置信候选每天不超过配置上限。模拟日上限和账期预算用尽：暂停项仍为 queued，带原因和下次可运行时间；小时补偿不得提前启动，到期后重新检查预算并恢复同一条目，不重复发现或收费。

重点故障注入：D1 已写入但 Workflow 未启动；转写任务已提交但响应丢失；摘要写入前重启；同一个任务重复触发；一个来源失败其余完成。每种情况检查状态可恢复、原链接不丢、不会静默重复收费。

安全测试覆盖未登录读写、错误 JWT audience/签名/过期、伪造邮件头、其他域名绕过 Access、跨站写请求、原文/模型脚本注入、私网地址与跳转抓取、凭证泄漏。

## 真实来源与手机端决定能否上线

在 staging 使用产品负责人提供的至少 5 人名单，先冻结 20 条人工确认相关的一手内容，覆盖各来源类型；至少一条是无现成逐字稿但有公开音频的长播客。正文取得率固定除以 20，失败不换样；正式摘要共 N 条，N 至少 16，全部核查，其中至少 ceil(0.9×N) 条正确呈现一手相关内容，关键经营数字和人物归因零编造。记录每条实际成本。同名、转述、无可用正文等负例另测，不混入这 20 条的分母。

Inoreader 的两小时配置初筛只判断可行性。质量对照须等双方实际输出可用，使用相同 URL、摘要要求与人工输入，单列人工补充及修正时间。账号、额度或时间不足记未测，不算产品失败。

访谈发现对照只给相同人物、别名、已登记节目和固定时间窗，事先保存的已知访谈核对集不输入系统。记录“已知核对集命中率”，不称全网发现率；第三方全网 Podcast 发现不纳入首版承诺。每日维护时间需后续七天观察，不能由初筛推算。

在 360px/390px 视口和真实手机上验证登录、日期/人物/类别筛选、详情证据、原文跳转后返回、收藏跨设备一致、部分失败与无更新的差异。冷启动页面能在普通移动网络下快速开始阅读，具体性能基线记录在首次 staging 报告中。

生产开启后观察 7 天。逐条对照 [PRD 验收表](prd.md#7-用真实样本和七天试运行判断是否成功)，验证 D1 备份恢复、应用版本回滚及日更失效提示。Cloudflare 真实 AI 调用属于计费集成验证，始终受配置预算约束。
