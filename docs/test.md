# 用来源真实性、任务恢复和手机闭环验收

本文件描述实现后的验证计划。当前没有应用代码，未执行单元、集成或端到端测试。

## 有风险的纯逻辑使用单元测试

- 日归档和日任务幂等：夏令时切换、UTC 跨日、漏触发后的补跑。
- URL 规范化、平台 ID 去重、同集多平台关联、错误合并撤销后收藏行为。
- 经营数字与币种/周期口径、缺正文时禁止生成正式摘要、引文与时间位置验证。
- JSON schema 失败、部分正文、同名嘉宾、仅被提及、推广内容的分类。
- 并发预算预留、调用失败后的结算、重复任务不二次扣款。

## 本地集成验证数据库与任务边界

使用 Cloudflare 本地运行环境、测试 D1/R2 和虚构 RSS/字幕 fixture，真实正文不进公开仓库。覆盖 200/304/403/429/5xx、源站超时、feed 回溯、日期缺失和坏 XML。

新增完整度用例：RSS 只给首段、提供方返回 200 但缺中间字幕、处理只读前 2,000 字符、部分分块失败。检查这些材料都不能变成完整摘要。白名单内容的标题没有 AI 或播放量低时，仍须取得正文再判定，或者明确留在待处理列表。

重点故障注入：D1 已写入但 Workflow 未启动；转写任务已提交但响应丢失；摘要写入前重启；同一个任务重复触发；一个来源失败其余完成。每种情况检查状态可恢复、原链接不丢、不会静默重复收费。

安全测试覆盖未登录读写、错误 JWT audience/签名/过期、伪造邮件头、其他域名绕过 Access、跨站写请求、原文/模型脚本注入、私网地址与跳转抓取、凭证泄漏。

## 真实来源与手机端决定能否上线

在 staging 使用产品负责人提供的名单，人工标注并核验 20 条。分别记录发现率、正文取得率、内容相关性、人物归因、数字准确性和每条实际成本；可用的长播客样本必须至少包含一条没有现成逐字稿的音频。对无正文的情形验证预告与待处理状态。

Inoreader 对照采用同样内容与任务；单条摘要和人物访谈发现分开测量。前者允许输入相同 URL，后者只给人物名单与固定时间窗，事先保存已知相关访谈作为核对集。比较人工确认次数与操作时间，不根据工具名称判定优劣。

在 360px/390px 视口和真实手机上验证登录、日期/人物/类别筛选、详情证据、原文跳转后返回、收藏跨设备一致、部分失败与无更新的差异。冷启动页面能在普通移动网络下快速开始阅读，具体性能基线记录在首次 staging 报告中。

生产开启后观察 7 天。逐条对照 [PRD 验收表](prd.md#7-用真实样本和七天试运行判断是否成功)，验证 D1 备份恢复、应用版本回滚及日更失效提示。Cloudflare 真实 AI 调用属于计费集成验证，始终受配置预算约束。
